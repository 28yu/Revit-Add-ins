## 今回のリリースに入る変更（v2.7.2 → 現在の main）

新機能は無い（`features.json` の変更は不要）。改善と修正のみ。

- **梁レベル色分け（天端／下端）**: 表記する文字の手入力／レベル差で色を各階共通に（塗潰し領域タイプ `梁天端色_<±値>` に保存）／
  階ごとの凡例を凡例ビューで作成・同名の確認・実行後に開く／凡例の上書きでビューが消える不具合の修正／
  梁ラベルを「文字」か「梁タグ」で選択／鉛直ブレースには付けない・水平ブレースはチェックボックス
- **耐火被覆色分け**: 凡例の上書きでビューが消える不具合の修正
- **リアルタイムレンダリング**: 大きなモデルで落ちる対策／「表示」の設定（太陽の光・照明器具・時間帯・空と背景色・地面と地面の色・単色・PNG 透明）／
  3D ビューのレンダリング設定を最初の見た目に／フェーズの上書きのマテリアル
- 詳細は `Docs/DEVLOG.md`（RealtimeRender の 2026-10-19・10-20 追記、BeamTopLevel の 2026-10-19・10-20 の節）

## 公開の手順（順番が大事）

バージョン番号は **2.8** を想定（新しい設定項目が増えたため。パッチ扱いなら 2.7.3。決めるのは運営者）。
以下は 2.8 の場合。

1. **有効期限を1年延ばす**: `Licensing/ExpiryManager.cs` の `ExpiryDate`（現在 2027-10-31）→ 公開日の1年後に。
   `Properties/AssemblyInfo.cs` は CI が書き換えるので任意（ローカルビルド用に 2.8.0.0 にしてもよい）。
   `claude/*` に commit・push（main に自動マージ）。⚠ commit と push は別々の Bash で
2. **下書きリリースを作る**: `git push origin origin/main:refs/heads/release/v2.8`
   → `build-and-release.yml` が全6バージョンをビルドし、両リポジトリに下書きと `28Tools_Setup_v2.8.exe` を作る（約4分）
3. **運営者の作業**: 下書きの exe を実機でダウンロードして確認（警告の有無）。
   両リポジトリの下書きの本文に `release-notes.md` の文章を貼る（Claude はリリース編集が 403 でできない）
4. 運営者が「公開して」と言ったら: `git push origin origin/main:refs/heads/publish/v2.8`
   → `publish-release.yml` が両リポジトリを公開する。サイトのダウンロードボタンはこの時点で新版になる
5. **公開の後に**マニュアルとサイトを更新する（先にやると、マニュアル・新着だけ新版でダウンロードは旧版になる）
   - アドイン側: `Features/*.md` の3本を `Docs/Features/` に上書きコピーして `claude/*` に push
     → `notify-site.yml` がサイトのマニュアルを作り直す（数分）。このフォルダ（`Docs/ReleasePrep/v2.8/`）はその commit で削除してよい
   - サイト側（28tools-download）: `git apply <このフォルダ>/site-news-v28.patch` → 日付（`2026/10`）を公開した月に直す →
     `claude/*` に push（自動で PR 作成・マージ → 本番）。サイトの `CLAUDE.md` の「現在のバージョン」も v2.8 に直す
     （機能数は 24 のまま。`addins.html` の機能カード・機能数の変更は不要）
6. **Notion**: リリースDB（907878c5-…）に `対象=アドイン (Revit-Add-ins)` で v2.8 を記録、決定事項ログに追記、
   「v2.8 公開」タスクを完了に
7. `STATUS.md` / `TASKS.md` / `Docs/DEVLOG.md` に公開の記録を残す
